# US-101 — Order lookup, health check and lookup audit

## User story

As a **Customer**,
I want to look up my Order by Order ID and email,
so that I can see its status, items and return deadline without contacting support.

As **Support Staff**, I need every lookup attempt recorded as an Audit Event, so that later disputes can be traced.

## Scope

This story establishes the skeleton every later story builds on:
- `create_app()` with a shared in-memory DB (AD-2)
- `UnitOfWork` (AD-3)
- `Clock` and `format_ts` (AD-6)
- money helpers (AD-5)
- the full error model (AD-8)
- `AuditService` with the `ActionType`/`Outcome` enums and the audit details models (AD-4)
- seed data (AD-10)
- the single import root (AD-11)

It creates **only** the `products`, `orders`, `order_lines` and `audit_events` tables. The `returns` and `return_lines` tables arrive in US-102. Until then, the lookup response returns `quantity_returned = 0` and `returns = []`, computed through the same derived-sum query path once the tables exist (AD-9: `ReturnRepository.returned_quantities` returns `{}` for now).

## Acceptance criteria

**AC-1 — Successful lookup**
**Given** seeded Order `ORD-1001` with status `delivered`, Delivery Date D, and customer email `asha@example.com`
**When** `GET /orders/ORD-1001` is called with header `X-Customer-Email: Asha@Example.com `
**Then** the response is 200 and contains `order_id`, `status`, `order_date`, `delivery_date`, and `lines[]`, where each line has `sku`, `name`, `quantity`, `unit_price` (2dp string), and `quantity_returned`
**And** `return_eligible_until` equals D + 30 days
**And** the email is not present anywhere in the response.

**AC-2 — Not-delivered Order**
**Given** a seeded Order with status `shipped`
**When** it is looked up with the correct email
**Then** the response is 200, with `delivery_date: null` and `return_eligible_until: null`.

**AC-3 — No Order enumeration**
**Given** an unknown Order ID, and separately a known Order ID with the wrong email
**When** each is looked up
**Then** both return 404 with an identical body `{"error": {"code": "NOT_FOUND", "message": "Order not found"}}`.

**AC-4 — Missing email header**
**Given** no `X-Customer-Email` header
**When** `GET /orders/ORD-1001` is called
**Then** the response is 422 with `{"error": {"code": "INVALID_REQUEST", ...}}`.

**AC-5 — Lookup is audited**
**Given** any lookup attempt from AC-1 to AC-3
**When** it completes
**Then** exactly one Audit Event is stored, with `action = ORDER_LOOKUP`, `outcome` of `found` or `not_found`, the supplied `order_id`, a UTC `occurred_at` taken from the injected Clock, and a `details_json` that contains no email
**And** `occurred_at` matches `YYYY-MM-DDTHH:MM:SS.ffffffZ`.

**AC-6 — Health check**
**Given** the app is running
**When** `GET /healthz` is called
**Then** the response is 200 `{"status": "ok"}`
**And** if `HealthService.check()` fails (simulated in a test), the response is 503 `{"error": {"code": "UNHEALTHY", ...}}`.

**AC-6b — Framework errors use the same shape**
**Given** an unknown path, a wrong HTTP method, and an unexpected exception (simulated)
**Then** the responses are 404 `NOT_FOUND`, 405 `METHOD_NOT_ALLOWED` and 500 `INTERNAL_ERROR`, all in the `{"error": {...}}` shape
**And** no validation error message echoes the input value.

**AC-7 — Seed data and docs**
**Given** a fresh `create_app(clock=FixedClock(T))`
**Then** the seed dates are documented offsets from T, and the seed contains at least:
- an Order delivered within the last 30 days
- an Order delivered more than 30 days ago
- a `shipped` Order
- a `cancelled` Order
- a Product with `returnable = false`
- a Line Item with quantity ≥ 2

**And** `GET /docs` returns 200, and the OpenAPI document lists `/orders/{order_id}` and `/healthz` with `ErrorResponse` declared for their 404, 422 and 503 responses.

**AC-8 — Quality**
- `pytest` passes.
- Coverage of `domain/` and `services/` is ≥ 90%.
- No call to `datetime.now`, `datetime.utcnow` or `date.today` exists outside `core/clock.py`.
- `api/` does not import `repositories/`.
- No file imports `retail_agent` without the `src.` prefix (AD-11).
- `tests/test_architecture.py` enforces these three rules.
