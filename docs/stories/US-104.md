# US-104 — Audit Trail API, Docker image and CI with security scans

## User story

As **Support Staff**,
I want to read the Audit Trail filtered by Order, action and time,
so that I can explain any return or refund outcome to a customer in one look.

As the **team**, we want every PR built, tested and scanned automatically, and the service runnable in Docker, so that `main` always meets the PRD's quality bar.

## Acceptance criteria

**AC-1 — List the Audit Trail**
**Given** existing Audit Events
**When** `GET /audit-events` is called
**Then** the response is 200 `{items, total, limit, offset}`, with `items` ordered newest first (`seq DESC`)
**And** `limit` defaults to 50.

**AC-2 — Filters**
**Given** events for several Orders and actions
**When** the filters `order_id`, `action` (an `ActionType` value), `from` (inclusive) and `to` (exclusive), both ISO-8601 UTC, are used alone or combined
**Then** only matching events are returned, and `total` reflects the filter.

**AC-3 — Validation**
**Given** `limit = 0`, `limit = 201`, a negative `offset`, an unknown `action` or a malformed timestamp
**Then** the response is 422 `INVALID_REQUEST`.

**AC-4 — Append-only**
**Given** the OpenAPI document
**Then** no `PUT`, `PATCH` or `DELETE` operation exists on any audit path
**And** `AuditRepository` exposes no update or delete method.

**AC-5 — UJ-2 end to end**
**Given** a denied return request for an Order because the item is not returnable
**When** `GET /audit-events?order_id=<id>` is called
**Then** the response shows the `RETURN_REQUESTED`/`denied` event with `denial_reason: ITEM_NOT_RETURNABLE` and its timestamp.

**AC-6 — /docs complete**
**Given** `/openapi.json`
**Then** every endpoint in the architecture's API table is present, with its request and response schemas and its documented error responses.

**AC-7 — Docker**
**Given** the `Dockerfile` (`python:3.12-slim`, uv copied from `ghcr.io/astral-sh/uv:0.13.7`, `uv sync --frozen --no-dev`, a non-root user, uvicorn with one worker on port 8000)
**When** the image is built and run
**Then** `GET /healthz` returns 200 and `/docs` loads
**And** no secrets or `.env` files are copied into the image (a `.dockerignore` excludes them).

**AC-8 — CI**
**Given** a pull request
**Then** `.github/workflows/ci.yml` runs these steps, and any failure fails the build:
- `astral-sh/setup-uv` (uv 0.13.7), then `uv sync --frozen`
- `uv run pytest` with the 90% coverage gate on domain + services
- `uv run pip-audit` (fails on any known vulnerability)
- `uv run bandit -r src --severity-level medium`
- a gitleaks secret scan
- a Docker build followed by a `/healthz` smoke test

**And** the README documents that these checks are required status checks under branch protection on `main`.

**AC-9 — Quality**
- `pytest` passes and coverage is ≥ 90%.
- `pip-audit` and `bandit` are clean locally.

## Dev tasks

1. `AuditRepository.list(filters, limit, offset)` and `count(filters)`, ordered by `seq DESC`.
2. `AuditService.list(...)` (an entry point with a read transaction), plus the `GET /audit-events` router with validated query parameters (`from_: datetime | None = Query(None, alias="from")`) and an `AuditEventView` / `AuditPage` schema.
3. Tests:
   - API tests for AC-1 to AC-5
   - an OpenAPI test for AC-4 and AC-6
4. `Dockerfile` and `.dockerignore` (excluding `.env*`, `.venv`, `.git` and tests).
5. `.github/workflows/ci.yml` with the AC-8 steps. Add `pip-audit` and `bandit` as pinned dev dependencies in `uv.lock`, and pin the gitleaks action to a commit SHA.
6. Update `README.md` with how to run locally, run in Docker, and run the tests and scans.
7. QA: create `docs/qa/gates/US-104.yml` with status PASS.
